# NFT Flip Bot — Telegram-бот для поиска выгодных NFT-флипов на TON

Мониторит маркетплейсы **Getgems** и **Tonnel** через Playwright (без API-ключей), находит недооценённые NFT и отправляет уведомления в Telegram.

## Возможности

- **/start** — главное меню с кнопками
- **FSM-настройка фильтров**: мин./макс. цена, коллекции, мин. прибыль, макс. возраст листинга
- **SQLite** — хранение настроек и отправленных лотов (анти-дубликат)
- **Фоновый мониторинг** каждые 10–15 минут
- **Критерии выгодности**: скидка ≥20% от floor, редкость атрибутов, ликвидность (объём 24ч > 100 TON, холдеры > 200, ставки), возраст листинга, чистая прибыль с учётом комиссии 2%, фильтр скамов
- **FastAPI + Uvicorn** с вебхуком и healthcheck `/health`
- **Playwright** для обхода блокировок

## Структура

```
config.py        — загрузка .env
database.py      — SQLite (настройки, отправленные лоты, время проверок)
parsers.py       — парсеры Getgems/Tonnel (Playwright)
analyzer.py      — NftAnalyzer.is_profitable()
handlers.py      — команды и FSM
monitor.py       — фоновый цикл мониторинга
main.py          — FastAPI, вебхук, запуск
test_parser.py   — тест парсера без бота
Dockerfile       — python:3.10-slim + Playwright + healthcheck
```

## Локальный запуск

```bash
# 1. Установка зависимостей
pip install -r requirements.txt
playwright install chromium

# 2. Настройка
cp .env.example .env
# Впишите BOT_TOKEN от @BotFather

# 3. Запуск (без WEBHOOK_URL — режим поллинга)
python main.py
```

Тест парсера:

```bash
python test_parser.py "Ton Punks"
```

## Деплой на Railway (бесплатно)

1. Создайте репозиторий на GitHub и загрузите проект.
2. На [railway.app](https://railway.app) нажмите **New Project → Deploy from GitHub repo**.
3. Railway сам определит Dockerfile и поднимет контейнер.
4. В **Variables** добавьте:
   - `BOT_TOKEN` — токен от BotFather
   - `WEBHOOK_URL` — публичный URL приложения (виден в Railway: `https://<app>.up.railway.app`)
5. Railway автоматически подставит `PORT`. Контейнер поднимется, вебхук зарегистрируется, мониторинг запустится.
6. Healthcheck `/health` не даст Railway «усыпить» контейнер.

> ⚠️ Если `WEBHOOK_URL` не задан — бот работает в режиме поллинга (подходит для локального запуска).

## Переменные окружения

| Переменная | Описание | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | Токен бота (обязательно) | — |
| `WEBHOOK_URL` | Публичный URL (вебхук) | пусто (поллинг) |
| `PORT` | Порт сервера | 8000 |
| `PROXY_URL` | Прокси (опционально) | пусто |
| `MONITOR_INTERVAL_MINUTES` | Интервал цикла | 15 |
| `MIN_COLLECTION_CHECK_INTERVAL_MINUTES` | Пауза между проверками коллекции | 10 |
| `DEFAULT_MIN_PRICE` / `DEFAULT_MAX_PRICE` | Диапазон цен | 1 / 500 |
| `DEFAULT_MIN_PROFIT` | Мин. прибыль | 5 |
| `DEFAULT_MAX_LISTING_AGE` | Макс. возраст листинга, мин | 120 |
| `LOG_LEVEL` | Уровень логов | INFO |

## Критерии выгодности

1. **Ценовая аномалия**: `listing_price < floor_price * 0.80`
2. **Редкость**: сумма `(редкость_атрибута * 0.1)` > 5 — бонус; атрибут с редкостью < 3% — плюс; > 3 атрибутов с редкостью > 20% — игнор
3. **Ликвидность**: объём 24ч > 100 TON, холдеры > 200, есть ставки
4. **Возраст листинга** ≤ заданного (по умолч. 120 мин)
5. **Чистая прибыль**: `(floor * 1.05) - цена - комиссия 2%` ≥ минимума
6. **Анти-скам**: коллекция старше 3 дней, без "Mystery"/"Airdrop"/"Giveaway"

## Примечания

- БД `data.db` создаётся автоматически.
- Логи пишутся в консоль и `bot.log`.
- Ошибки парсинга не роняют бота — цикл продолжается.
- Один и тот же лот не отправляется повторно (проверка по ID).
